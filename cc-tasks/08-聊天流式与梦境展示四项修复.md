# 08 — 聊天流式与梦境展示四项修复（mobile）

> 四个子任务相互独立，**均可并行**；无前置依赖。改前先读 `docs/mobile/flutter-structure.md`。
> 涉及文件：`lib/controllers/chat_controller.dart`、`lib/controllers/dream_controller.dart`、`lib/widgets/chat_widgets.dart`、`lib/widgets/dream_widgets.dart`。

## 任务 A：多气泡逐条出现（而非同时刷出）

### 现象
回复按换行切成多个气泡后，多个气泡几乎同时出现、各自并行跑打字机动画，观感混乱。

### 根因（已定位）
`chat_controller.dart` 中有两条追加回复的路径：

1. `_appendReply()`（同步 HTTP 回复路径，约 L424）：**已经**做了逐条延迟（100–1000ms 随机 + 中间态 `himTyping`），这条路径行为基本正确。
2. **mobile poll 路径**（`pollMobile` 处理 `fresh` 消息处，约 L327）：`for (final part in parts) { sent.add(... animate: true) }` 一次性把所有分段全部 add 进列表再统一 `notifyListeners()`——这就是"同时出现"的来源。

另外即使有延迟，气泡 N+1 出现时气泡 N 的 reveal 动画可能还没放完（`_revealCps = 40`，长段落要几秒），两个动画并行。

### 修复要求
1. 把 poll 路径的分段追加改为复用 `_appendReply()` 同款的逐条节奏（抽一个公共的 `_appendSegments(List<String> parts)`，两条路径共用）。
2. 升级节奏逻辑：**下一个气泡等上一个气泡 reveal 完成后再出现**。实现建议：`_appendSegments` 里按 `part.characters.length / 40 * 1000 ms`（与 `chat_widgets.dart` 的 `_revealCps` 一致，抽成共享常量）+ 一点随机间隔来 await；期间维持 `himTyping = true`。
3. 队列化：若前一批分段还在播放中又来了新消息，追加到同一队列尾部顺序播放，不允许并行。

### 验收
- 后端一次回复含 3 段换行文本 → 手机上 3 个气泡依次出现，每个都等前一个打完；期间显示"正在输入"。
- 主动消息（poll 路径）同样逐条出现。

## 任务 B：历史记录每次都重新"流式一次"

### 现象
（此前修过但复现/未修净）打开 app 或回到聊天页时，历史消息重新播放打字机动画。

### 排查方向（按嫌疑度排序）
1. `chat_widgets.dart` L155 的 ListView item key：`ValueKey('chat-$globalMessageIndex-...')` 含 **globalMessageIndex**。历史加载完成/上滑展开更早消息（`_revealOlder`）/折叠数变化时索引整体平移 → key 全变 → `HimMessage` State 重建 → 凡 `animate == true` 的消息重新播动画。**修法：key 改为稳定的消息标识**（给 `ChatMessage` 加自增/uuid id，key 只用 id），不含索引。
2. `markRevealStarted()`（controller L111）：用 `sent.indexOf(message)` 按对象身份找消息，若消息对象在别处被重建则找不到，`animate` 永远清不掉 → 每次 widget 重建都重播。**修法：改用消息 id 定位；且置位后立即生效（当前不调 notifyListeners 是刻意的，保持，但要保证下次 build 拿到的是 animate=false 的对象）。**
3. 确认 `_messagesFromDay()`（历史加载）构造的消息 `animate` 恒为 false（目前是，勿回归）。
4. 确认 `refresh()`/重连流程不会把已播放过的 `sent` 消息重新标 `animate: true`。

### 验收
- 冷启动加载历史：任何历史消息不播动画，直接完整显示。
- 上滑展开更早消息、加载更早分页：已在屏的消息不重播动画、不闪。
- 新回复只播一次；切到别的 tab 再切回来不重播。

## 任务 C：梦境对话叙事分段渲染（向 client 靠拢）

### 现象
梦境页所有回复都是同一种气泡，没有像桌面端那样按"语言/动作/环境/心理"分视觉样式。

### 背景（后端已就绪，不改后端）
- 后端 `POST /dream/chat` 的响应**已经**返回 `segments`（`[{type, text}]`，type ∈ `say/do/env/feel/narration`）和 `segmented_content`（去标记纯文本），见 `Emerald-presence/core/dream/dream_pipeline.py` L349-357。
- 标记语法（万一需要本地兜底解析）：XML `<say>/<do>/<env>/<feel>` 或 Markdown 整行 `*动作*`、`_心理_`、`> 环境`，其余为 say/narration。

### 修复要求
1. `backend_client.dart` 的 dream chat 响应模型增加 `segments` / `segmented_content` 字段解析。
2. `dream_controller.dart` `_send()`：优先用 `segments` 渲染；无 segments 时退回现在的 `_splitReply` 纯文本分段。
3. `dream_widgets.dart` 新增分段样式（参考桌面端 `Emerald-client/src/windows/dream/components/DreamChatPanel.tsx` 的视觉分层，不必像素级一致，用现有 `YxPalette` 配色体系）：
   - `say`：正常气泡；
   - `do`（动作）：斜体/无气泡边框的弱化行；
   - `env`（环境描写）：居中弱化文本，可复用现有 `DreamSceneLine` 的分隔线风格；
   - `feel`（心理）：斜体 + 更弱的颜色；
   - `narration`：同 env 或普通弱化文本。
4. 打字机动画规则与主聊天一致（配合任务 A 的逐条节奏；若任务 A 未合并也不阻塞，本任务先保持现状节奏）。

### 验收
- 梦境中一条含 `*动作*` / `> 环境` / 对白混排的回复，渲染为不同视觉样式的多个块，顺序与原文一致。
- 后端异常/无 segments 时退回纯文本，不崩。

## 任务 D：返回最新箭头——下滑即隐藏

### 现象
上滑后出现"回到最新"箭头（正确），但只要距底部 >260px 就一直显示，遮挡内容。期望：**用户开始向下滑（朝最新方向）时箭头立即消失**；再次向上滑时才重新出现。

### 位置
`chat_controller.dart` `_handleScroll()`（约 L538）：当前 `show = maxScrollExtent - pixels > 260`。

### 修复要求
1. 记录上一次 `pixels`，判断滚动方向（或用 `position.userScrollDirection`）。
2. 规则：向上滑且距底 >260 → 显示；**向下滑 → 立即隐藏**（即使距底仍 >260）；回到距底 <260 → 隐藏。
3. 点击箭头回底后隐藏的现有逻辑保留。
4. 梦境页如有同款箭头逻辑，一并对齐（检查 `dream_controller.dart`）。

### 验收
- 上滑出现箭头 → 向下滑动任意距离箭头立刻消失 → 再上滑重新出现。
