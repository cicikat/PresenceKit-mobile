## 1. 单次生成，多端分发

- [ ] mobile stream仅作为同一Reality turn的作用域隔离分发出口。复用既有生成、工具与记忆写入链路，禁止手机专属LLM推理链，禁止因新增订阅/重连/补收而重复工具执行或记忆写入。既有一次turn内部的多轮模型/工具调用仍按原逻辑执行，不能把“单次生成”误解为只允许一次LLM API调用。
- [ ] 明确eligible来源及owner/char/domain范围，保留request_id、turn_id、msg_id各自语义；不能把Dream、活动独立窗口或无授权来源自动广播到主聊天。手机与桌面订阅数不改变原执行链次数。重连不得重新POST一轮生成；未知结果继续沿工单42的身份/重试合同处理。

原工单“mobile专属stream分支”改为上述**同一turn的分发出口**，不得据此创建另一套推理或工具调度。

## 2. 内容权威、队列与序号

- [ ] 明确层级：**最终持久化消息是内容权威；队列记录待投递；WS承载实时传输**。流片段只是暂态展示，最终内容、分段、附件/贴纸等可恢复展示字段以对应持久消息为准。未持久成功不得标记为已持久完成；历史补收不生成新的业务回复。
- [ ] R2保留全局ACK删除前缀、seq、TTL、既有HTTP/原生inbox合同。WS片段不推进最终ACK，WS与HTTP不得作为互不协调的消费者各自推进同一队列游标。前后台交接复用工单42的完整inbox及精确确认。
- [ ] **验收门槛**：队列被其他消费者ACK清理后，手机仍可通过现有HTTP持久历史读取同一授权范围内的完整最终消息，按稳定身份完成对账，不能仅依赖/mobile/poll或重发原请求。施工前逐项核对日期/范围发现、跨日补收、分页或读取边界、身份字段、正文及富媒体元数据覆盖；正文恢复与附件实际资源仍可用应分别验证。历史读取不得伪造投递seq或推进队列ACK。
- [ ] 区分持久事件/投递seq与临时stream chunk序号：沿用现有持久序号的命名空间和用途，不假定队列seq就是历史全局游标；chunk序号仅用于同一turn、同一流代际内排序/去重，不可充当持久游标、消息身份或最终ACK。缺失片段通过最终消息/HTTP对账恢复，不要求永久保存全部token。

限制：已有chat-log入口不等于已证明每一种回复及元数据都可完整补收，本项目前未验收。若字段/身份/范围覆盖不足，应标明阻塞与缺口，提出最小兼容方案并核对合同后再施工；不得依赖提前实现R3来宣称达标。历史已被用户删除、撤回、权限移除、保留策略清理或媒体资源失效时，不能承诺恢复；必须遵守相应不可用结果。这里的“不丢失最终回复”以持久成功、仍获授权且处于保留范围为前提。

## 3. 流式安全边界

- [ ] 只输出经必要过滤且明确可向用户展示的正文，采用允许输出内容的明确边界。工具调用/参数/结果、内部生成内容（推理、系统提示、草稿和控制标记等）、跨owner/char信息不得进入mobile stream；原有独立工具观测接口不因此并入正文流。
- [ ] 在发送每个正文片段前保证过滤成立，覆盖跨chunk边界的控制标记及敏感内容；不得依赖最终回复清洗撤回已发送内容。无法安全判定的片段应缓冲，无法建立增量安全边界时降级为过滤后的完整最终消息，不得为首token指标提前泄露。最终持久消息仍具内容权威，HTTP/WS展示统一按其对账。

限制：本单不宣称现有生成输出已可直接安全流送。过滤位置、片段边界及来源隔离需要实现证据与故障注入验收；最终对账可以纠正展示差异，不能撤销已经发生的信息泄露。

## 4. Android生命周期

- [ ] R2只承诺App前台实时连接。进入后台允许断开WS并使接收代际失效；回到前台重新校验身份/权限，通过HTTP持久历史及既有队列补收，再协调实时展示。复用现有恢复、inbox和通知链路，后台不承担WS首token或即时到达承诺。
- [ ] 前台使用有界心跳、退避、网络取消与重连策略，明确停止条件；禁止为WS保活引入无限重连、高频心跳、额外常驻服务或绕过系统后台限制。现有后台signal/poll补偿保留，Doze/OEM/进程被杀后的时效继续observe。

## 5. 连接及权限隔离

- [ ] 定义独立/ws/mobile（或等效隔离入口），服务端核验owner、char、client_type及连接代际，身份来自有效凭据和会话绑定，不能信任客户端自报。与桌面连接槽隔离，不能复用会替换桌面连接的/ws/desktop。旧mobile token只在其原有有效权限内兼容，不授予admin、ws.desktop或更宽owner/char权限。
- [ ] 权限校验覆盖握手、分发及连接更新，不能握手成功后永久放行。服务端确认撤权或角色切换生效后，旧订阅立即失去后续事件接收资格，待发送事件同样核验；客户端切换时立即隔离旧代际。失效连接的ACK/pong/final和迟到回包不得修改新连接状态、推进新作用域ACK或覆盖新角色消息。
- [ ] 旧流final不得直接写入新代际UI；若仍需恢复旧turn，必须经当前授权的HTTP持久历史与稳定身份对账，不能通过重放旧连接帧绕过隔离。撤权/切换确认时点与服务端失效机制必须可测试，不得仅依赖客户端隐藏。

限制：“立即失去资格”指服务端变更生效后的后续分发闸门；已经写入网络缓冲或到达客户端的字节不可撤回，客户端需以代际/作用域拒绝旧帧。离线时服务端尚未收到的本机切换不能声称已使远端订阅失效；恢复通信必须先完成重新绑定/校验，才可展示实时事件。

**流片段和最终消息身份**：`request_id` 关联输入请求；若生成开始时尚无持久 `turn_id/msg_id`，暂态只能以当前连接代际内的 `request_id + stream_id` 关联，不能捏造最终身份。持久化成功后才发送含 `stream_id + turn_id + msg_id` 的绑定及 final；HTTP、历史、队列必须返回同一绑定，客户端按身份替换暂态而非新建成功回复。分段共享同一最终消息身份，并按段序号/出现次数合并。本次 `final_only` 不发送暂态片段，绑定和 final 同帧，且 `msg_id=turn_id`；不得将桌面的临时 stream msg_id 当成手机最终身份。

**失败后的临时内容收尾**：生成失败、持久化失败、取消不发送成功 final。若将来开启增量流，终态必须区分 failed/cancelled/unknown，暂态正文从成功 transcript 移除，停止生成指示并保留原请求的失败或待对账状态；断线/超时不能推断后端取消或允许重生成。通过同一 request_id 的 receipt/已持久历史恢复最终结果；已最终化消息不可被迟到失败降级。缺少终态帧时也须有本机期限，停止指示并转 HTTP 对账。当前 `final_only` 没有半句气泡，沿既有发送失败/不确定结果状态收尾。

## 范围与依赖
